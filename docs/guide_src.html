KICK/FRAME

Beat-synced geometric visualizers and cover art for techno tracks

User guide · Kickframe 0.1.0 · Every image in this document was rendered by Kickframe itself.

Kickframe turns an audio track into a music video of thin, precise line geometry that moves with the beat. It listens to the track, works out the exact tempo and beat grid, measures the kick, bass, mids and hi-hats on every video frame, and drives a choice of twelve visual styles, including two fractals, from those signals. It also draws square cover art in the same visual language, at the 3000×3000 size streaming platforms ask for.

Everything is drawn with code (Cairo vector graphics, encoded to H.264 by ffmpeg), so output is crisp at any resolution and the same command always gives the same result.

01Installation

02Quick start

A full render of a long track takes minutes, so work in three steps: look at a few frames, then a short preview with sound, then the whole track.

  1. Look first with stills. A handful of PNG frames takes seconds. Pick times from different parts of the track: intro, a groove, the breakdown, the peak. 
    kickframe stills track.mp3 --style tunnel --at 60 300 480 763
    This writes still_tunnel_0060.00s.png, still_tunnel_0300.00s.png and so on. The first run also analyses the track and caches the result as track.30fps.controls.npz; later commands reuse it instantly.
  2. Render a short preview with sound: 
    kickframe video track.mp3 --style tunnel --start 480 --duration 30 --with-audio -o preview.mp4
  3. Render the whole track. Using a work folder means an interrupted render resumes where it stopped: 
    kickframe video track.mp3 --style tunnel -o track_tunnel.mp4 --workdir work_tunnel
    The video is silent unless you add --with-audio.
  4. Make the cover: 
    kickframe cover ngons -o cover.png
kickframe cover ngons -o cover_title.png --title BERLIN_1 --subtitle "136 BPM"

No track yet? Use synthetic mode

--synthetic replaces the audio with a generated beat grid. It is a four-section arrangement (intro, groove, build, peak) of equal length, which is handy for loops, testing and trying styles.

kickframe video --synthetic --bpm 136 --bars 32 --style bold -o loop.mp4
kickframe stills --synthetic --bpm 136 --bars 64 --style atom --at 14 42 70 100

The video-style images in this guide were made this way: 64 bars at 136 BPM (about 113 s), with 16 bars per section. Synthetic mode keeps the kick running throughout, so it has no breakdowns. The breakdown examples in section 5 were rendered through the Python API with the kick switched off.

03How your track is analyzed

The first time you use a track, Kickframe decodes it with ffmpeg and builds a set of control signals, one value per video frame. It saves them next to where you run the command as <track>.<fps>fps.controls.npz, and later runs print using cached analysis … and skip this step.

Tempo and beat grid

Kickframe detects the BPM, or takes --bpm 136 as a hint, then fits the exact tempo and phase to the kick attacks in the waveform. Masters are rarely exactly on their nominal tempo. The example track berlin_1 runs at 136.026 BPM.

It then measures the grid error every 8 seconds and follows it, because edited arrangements drift and jump. berlin_1 shifts 75 ms at its breakdown, yet the grid stays within about 1 ms over all 17 minutes. Because of this, the visuals land on the kick from the first bar to the last.

Per-frame signals

SignalMeasured fromWhat it drives
Kick K and pulse35–120 Hz energy, smoothed over 2 beatsWhether the groove is running; the pulse that decays after every beat
Bass120–400 HzLine thickness, centre-mark size
Mids400–2500 HzBreathing and drift in breakdowns, the rose curve
HatsOnsets above 2.5 kHzTick marks around the rim
Intensity IBass + mids + highs, smoothed over 8 beatsHow busy the picture is: layer count, spokes, orbits; above 0.72 with the kick on counts as a peak
FlashKick returning after a breakA white flash on the re-entry
Beat / barThe fitted gridAll timing. The first kick re-entry decides which beat is "1" of the bar

Run the analysis on its own (it always re-analyses) to see what was detected:

kickframe analyze track.mp3 --bpm 136
duration 1021.4s  bpm 136.026  offset 0.112s  grid corrections -38..+37 ms  frames 30642  breaks/re-entries at [...]

The sample line above is illustrative. Your track's numbers will differ.

Note. The cache file is named after the track and the frame rate. If you change --bpm, replace the audio file or want a fresh result, add --reanalyze to stills or video, or run kickframe analyze.

04Video styles gallery

Kickframe has twelve styles: five originals (tunnel, atom, geometric, bold, subtle), five newer ones (horizon, scope, field, sphere, moire) and two fractals (branches, sierpinski). Each row shows one style through the four synthetic sections. As intensity rises, the picture grows denser, and the red accent appears on the downbeat (beat 1 of each bar) in peaks. Choose a style with --style NAME. The default is tunnel.

tunnel default · HUD off by default

The n-gon spiral as an endless tunnel. Triangles are born at the centre and flow outward through squares, pentagons, hexagons and octagons. Each kick surges the flow forward, the twist follows the track's energy, and every 24th layer is red.

atom HUD on by default

Electron shells with comet-trail electrons orbiting a phyllotaxis nucleus, over thinned morphing polygons. The number of shells grows with intensity, from two in the intro to six at the peak. A Lissajous figure appears in peaks and a rose curve in breakdowns.

geometric HUD on by default

Morphing n-gons whose number of sides changes every 16 bars (4 → 3 → 6 → 5 → 8 → 3 → 4 → 6), easing from one shape to the next over a bar. Kick ripples spread outward. Spokes appear above medium intensity, and up to three orbits carry small triangles and squares. The background grid switches between square and triangular each phrase.

bold HUD on by default

Nested squares that step 22.5° on every beat with an eased snap, alternating direction at higher intensity. In peaks you get a scrolling grid, sweeping horizontal bars and a red outer square and centre on each downbeat. In breakdowns the squares drift slowly instead of stepping.

subtle HUD off by default

Four thin squares in slow, continuous counter-rotation, with drifting dust and a soft breath on each kick. Squares appear one by one as intensity rises. This is the calmest style and gives by far the smallest files, which makes it good for long mixes and backgrounds.

horizon HUD off by default

A perspective floor rushing toward a polygon sun that sets behind the horizon. Each kick surges the travel forward, and the sun's slices scroll down once per beat. The sun changes shape every 16 bars (octagon, hexagon, 12-gon, square). In peaks a mirrored ceiling closes in to form a corridor and the sun turns red. Hats flicker the ticks along the horizon.

scope HUD on by default

A radial oscilloscope. One closed trace is shaped by three waves at once: bass sets the large lobes, mids the medium ones and hats the fine ripple. Recent traces linger as expanding echoes, and their number grows with intensity. The lobe counts change every 16 bars (3:8:24, 4:10:32, 5:7:28, 6:12:36). In peaks an XY Lissajous figure runs behind it and the trace turns red on the downbeat.

field HUD on by default

A lattice of small crosses. Each kick sends a wave out from the centre that enlarges the crosses it passes and turns them into an X, while the previous beat's wave is still travelling outward. The lit area grows with intensity. Hats light random crosses on every sixteenth note, and in peaks the wavefront turns red on the downbeat. In breakdowns the waves give way to a slow interference ripple driven by the mids.

sphere HUD on by default

A wireframe globe in real 3D, with bright lines on the front face and dim ones behind. It turns 15° per beat with an eased snap while the groove runs, and drifts in breakdowns. Every kick sends a scan line from pole to pole. The grid grows with intensity from 6×3 to 18×7 meridians and parallels. In peaks the equator turns red, and above medium intensity a tilted orbit with three triangle markers circles the globe.

moire HUD off by default

Two sets of concentric rings whose centres slide apart on every kick and back together between beats, so interference fringes bloom and collapse in time with the music. The pair slowly rotates, and the rings spread further as intensity rises. Hats shimmer the second set. In peaks a red wavefront spreads out on each kick, and in breakdowns the second set turns into slowly rotating hexagons.

Moiré patterns depend on the output resolution. Check them at your final --size, because a 720p preview shows different fringes than 4K.

Fractals

The two fractal styles are drawn from recursion, so the detail on screen follows the music. As a track builds, more levels of the fractal appear.

branches fractal · HUD off by default

A radial fractal tree. Trunks grow out from the centre and fork in two at every level, each child 70% the length of its parent. The number of generations follows intensity, from 4 in an intro to 9 at a peak. The newest generation grows in gradually rather than popping in. Each kick runs from trunk to tips as a pulse of length and brightness. The number of arms changes every 16 bars (6, 3, 4, 5). In breakdowns the mids open the branch angles so the tree spreads out. In peaks the tips turn red on the downbeat.

sierpinski fractal · HUD on by default

An endless zoom into six Sierpinski triangles that meet at the centre. Each kick pushes the zoom forward, and the camera drifts slowly in breakdowns. The pulse from each kick travels from the largest triangles to the smallest. Finer levels fade in as intensity rises, and in peaks every fourth level turns red. The HUD shows the total zoom factor, which passes ×100,000 within a few minutes.

Why the zoom never jumps: a Sierpinski triangle doubled in size about one corner contains an exact copy of itself at that corner. The style zooms about the shared centre, and every doubling it swaps the picture for the original size with one more level of detail. Line brightness depends on each triangle's size on screen, not on its recursion level, so the swap is invisible: the frames on either side of it match to within 0.005 of a grey level.

05How the visuals follow the music

Every beat: the kick pulse

On each kick the shapes expand slightly, brighten and thicken, then relax before the next beat. Inner layers react a fraction earlier than outer ones, which gives a ripple from the centre outward. These four frames are quarter-beats apart in the bold style at a peak:

Breakdowns: when the kick drops out

When the kick disappears, every style changes mode. Stepping rotation becomes a slow drift driven by the mids, shapes breathe with the pads, and geometric and atom draw a rose curve. The HUD label switches to BREAKDOWN, or to OUTRO in the last 10% of the track.

The drop: kick re-entry flash

When the kick returns after a break, the frame flashes white and fades over about two beats. The first re-entry in a track also sets which beat is counted as "1" of the bar, so bar numbers and red downbeats line up with the arrangement.

07More possibilities: formats and variants

One track, many formats

Because every style is resolution-independent, one analysis can feed a whole release campaign: a 1080p or 4K video for YouTube, vertical clips for Reels and Shorts cut from the strongest 15–30 seconds, and square loops for the Instagram feed. The analysis is cached after the first command, so the extra renders cost only drawing time.

# full video for YouTube
kickframe video track.mp3 --style sphere -o yt_sphere.mp4 --with-audio --workdir work_sphere
# 20-second vertical clip from the drop
kickframe video track.mp3 --style horizon --size vertical --start 480 --duration 20 --with-audio -o reel_drop.mp4
# square loop, no audio, for the feed
kickframe video track.mp3 --style moire --size square --start 600 --duration 15 -o feed_loop.mp4
# a 4K master
kickframe video track.mp3 --style scope --size 4k --crf 22 -o master_4k.mp4 --with-audio

Variants in two lines

Most styles keep their look in class attributes, so a variant is a short subclass with no new drawing code. Add these to kickframe/styles.py and register them in STYLES to use them from the command line, for example as --style tunnel_mono.

class TunnelMono(Tunnel):         # no red layers
    name, red_every = "tunnel_mono", 0

class TunnelDense(Tunnel):        # tighter spacing, more layers, hexagons to 12-gons
    name, SEQ, SP, NL = "tunnel_dense", [6, 8, 12], 8.0, 95

class HorizonTri(Horizon):        # a triangle sun
    name, SUN_SIDES = "horizon_tri", [3]

class MoireWide(Moire):           # wider ring spacing: bolder, slower fringes
    name, SP = "moire_wide", 28.0

class ScopeSharp(Scope):          # more lobes: a spikier trace
    name, LOBES = "scope_sharp", [(7, 14, 42)]

class GeoSquares(Geometric):      # geometric, but always squares
    name, SIDES = "geo_squares", [4]

class BranchesDuo(Branches):      # two mirrored trees, longer limbs
    name, ARMS, RATIO = "branches_duo", [2], 0.74

08Combining styles in one video

--style accepts more than one style name. There are two ways to combine them, and you can mix the two: layers draw several styles in the same frame, and sequences switch from one style to the next over the course of the track. Both work with video and stills, so you can check a combination with stills first.

Layers: +

Join styles with +. Add @opacity (0–1) to dim a layer. The first style is the base, and each further layer is blended on top with screen, so lines brighten where they cross and never hide each other. --blend add is punchier, and --blend over lets upper layers cover lower ones.

kickframe video track.mp3 --style "tunnel@0.3+scope" -o a.mp4           # dimmed tunnel behind a bright scope
kickframe video track.mp3 --style "horizon+sphere@0.9" -o b.mp4         # a globe rising over the floor
kickframe video track.mp3 --style "sphere+field@0.6" -o c.mp4           # globe on a lattice that waves on the kick
kickframe video track.mp3 --style "sierpinski@0.45+branches" -o d.mp4   # fractal tree over the endless zoom
Tip. Layers work best with contrast. Pair a busy, full-screen style at low opacity (tunnel, sierpinski, field, moire, horizon) with a clear central shape at full opacity (scope, sphere, branches, bold). Two dense styles at full strength blur into each other: in tunnel+scope, for example, the scope trace gets lost in the tunnel's lines.

Sequences: ,

Separate styles with commas to switch between them. Each item in the list can be a layered combination. --switch decides when to change, and the list repeats if the track has more sections than items.

--switchChanges style
32 (default), or any NEvery N bars, on the bar line
dropsEach time the kick returns after a breakdown, so every drop gets a new look
sectionsWhenever the kick stops or returns, so breakdowns and grooves alternate between items
kickframe video track.mp3 --style tunnel,sphere,branches,moire --switch 16 -o seq.mp4
kickframe video track.mp3 --style "tunnel,sierpinski+field@0.4" --switch drops -o drops.mp4
kickframe video track.mp3 --style geometric,subtle --switch sections -o sections.mp4

Transitions

With --transition fade (the default), the next style crossfades in over --fade-beats beats (default 4, one bar). The fade finishes on the downbeat, so a drop lands on the new look. --transition cut switches hard on the downbeat instead. Timeline: full control

To choose the exact moment of every change, use --timeline. It takes comma-separated WHEN=STYLE entries, and when you use it, --style is ignored. WHEN can be:

  • seconds, such as 288
  • m:ss, such as 4:48, or h:mm:ss
  • bN for bar N, counted the same way as the HUD, such as b129

Times snap to the nearest bar line, so switches always land on a downbeat. The first entry covers everything before the second, wherever it starts.

kickframe video track.mp3 -o set.mp4 --with-audio --workdir work_set \
  --timeline "0=subtle, 1:52=tunnel, b129=sphere+scope@0.5, 9:30=geometric, 12:40=sierpinski@0.4+branches"

A good way to build a timeline is to run kickframe analyze to see where the breakdowns and drops fall, then check each switch point with stills --timeline … --at before you render.

Notes

  • Combinations render without the HUD unless you pass --hud. When it's on, it shows the name of the current item.
  • A combination takes about the sum of its parts to render, plus both items during a crossfade. Use the drawing-cost table in section 11 to estimate.
  • Stills of a combination are named after the spec, for example still_tunnel-0.3-scope_0100.00s.png, or still_timeline_… for a timeline.

09Cover art

kickframe cover KIND -o FILE.png draws a square cover in the same visual language as the videos. The default size is 3000×3000, which is what streaming platforms ask for. Change it with --size, for example --size 1000 for a quick look. The geometry is resolution-independent, so every size shows the same composition.

Title and subtitle

Add text in the bottom-left corner with --title and --subtitle. Choose a font family with --font (default monospace; any installed font name works).

kickframe cover ngons -o cover_title.png --title BERLIN_1 --subtitle "136 BPM"

Parameters

Each cover kind takes parameters through --param KEY=VALUE, which you can repeat. Values are read as Python literals, so numbers and tuples work. Quote tuples in the shell: --param "sides=(3,4,6,8)".

11Render time, file size and resuming

Kickframe splits the video into 60-second chunks and renders them in parallel, one process per core, each piping frames to its own ffmpeg encoder. The chunks are then joined without re-encoding, and the audio is added if you asked for it.

Dense line art that moves every frame compresses poorly, so the files are large. Rough figures for a 17-minute track at 1080p30:

StyleFile size at --crf 24Render time (2 cores)
subtle~50 MB~10 min
bold~500 MB~10 min
atom / geometric~500 MB~15 min
tunnel~1.5 GB~25 min

The newer styles haven't been measured on a full track yet. To compare them, here is the drawing cost of one 1080p frame on one core, measured on the synthetic arrangement. Render time scales with it, divided by the number of cores. moire is also the densest picture and will likely produce the largest files, so raise --crf for it.

Stylems / frameStylems / frame
bold11subtle28
geometric19field34
atom21horizon36
sphere26tunnel49
scope28branches41
sierpinski77
moire108
  • Smaller files: raise --crf to 27–28. Above about 30 the thin red lines start to smear.
  • Smaller still: --preset medium gives files about 15% smaller for about twice the encode time.
  • Uploading: YouTube re-encodes anyway, so uploading the big file is fine.
  • More speed: more cores help almost linearly. Use --jobs to leave some free for other work.
  • Resuming: with --workdir DIR, finished chunks are kept. If a render is interrupted, run the exact same command again and it continues. A chunk is only saved once it is complete, so a stopped render never leaves a broken one behind.

12Writing your own style

A style is a Python class in kickframe/styles.py that subclasses Style and implements draw(self, ctx, s). ctx is a Cairo context and s holds the values for the current frame. Here is a complete, working example:

class Pulse(Style):
    """A single hexagon that pulses on every kick."""   # first line shows in `kickframe styles`
    name = "pulse"

    def prepare(self):
        # running state: integrate over ALL frames here, never inside draw()
        self.rot = np.cumsum(0.002 + 0.004 * self.c.I)

    def draw(self, ctx, s):
        rot = self.rot[s.f]
        self.layer_grid(ctx, s)
        self.layer_ripples(ctx, s)
        for i in range(3):
            r = (180 + 90 * i) * (1 + 0.15 * s.kick)
            red = s.peak and s.bib == 0 and i == 2          # red outer ring on peak downbeats
            ctx.set_line_width(1.5 + 2 * s.kick + s.bass)
            ctx.set_source_rgba(*(RED if red else INK), 0.3 + 0.6 * s.kick)
            poly(ctx, 6, r, rot * (1 if i % 2 == 0 else -1), self.CX, self.CY)
            ctx.stroke()
        self.layer_ticks(ctx, s, rot)
        self.layer_hud(ctx, s)

STYLES = {cls.name: cls for cls in (Bold, Geometric, Atom, Tunnel, Subtle,
                                    Horizon, Scope, Field, Sphere, Moire, Pulse)}

Canvas

Draw on a canvas 1080 units tall, centred at (self.CX, self.CY). Its width is self.VW and follows the aspect ratio. The same code then renders at every --size.

Shared layers

layer_grid, layer_ripples, layer_lissajous, layer_rose, layer_ticks, layer_brackets, layer_sweep, layer_flash and layer_hud. Helpers include poly(ctx, n, r, rot, cx, cy) for regular polygons and stepped_rotation(controls) for the 22.5°-per-beat motion.

Rules that keep renders correct

  • Put running state in prepare(). Anything that accumulates over time, such as rotation, flow or drift, must be computed there over all frames. Chunks render in separate processes, so state kept inside draw() would jump at every 60-second boundary.
  • Keep draw() deterministic. It should depend only on the frame index and precomputed arrays.
  • Stay in the visual language. Use a near-black background (BG), off-white lines (INK) and a single RED accent. Keep lines thin and avoid gradients apart from vignettes.
  • Register the style. Give it a docstring, add it to STYLES and add a row to the README table.

To try a style quickly with no track: kickframe video --synthetic --bpm 136 --bars 4 --style pulse --size 720p -o test.mp4.

New cover kinds work the same way. Write a function mycover(cv, **params) in kickframe/covers.py that draws on a 3000-unit square, and add it to COVERS. Its keyword arguments become its --param options automatically.
